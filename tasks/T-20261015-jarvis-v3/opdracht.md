## Wat de opdrachtgever vroeg

2026-10-15, bericht aan de cloud-uitvoerder: V2 structureel vervangen door een
veel eenvoudiger V3. De eigenaar neemt beslissingen; Jarvis voert uit. Eén
bron van waarheid voor taakstatus (een databasetabel), één state machine die
de database afdwingt, één mandaat per opdracht dat alle technische uitvoering
dekt (inclusief productie-uitrol en migraties wanneer het mandaat dat zegt),
`Voor jou` uitsluitend gevuld met echte eigenaarsverzoeken, en voltooiing op
grond van een gemeten eindresultaat.

Besluiten van de eigenaar: governance-paden blijven buiten ieder normaal
mandaat; migraties lopen over een gecontroleerde route zonder dat Jarvis de
verbindingsreeks ziet; de dispatcher start de routine via de API met een
GitHub-secret als token.

- [x] Tiende reparatieronde (QA ronde 10): BLK-H (`IF NOT EXISTS` registreert een bestaand object niet meer als nieuw; aangehaalde namen worden injectief afgebeeld, dus `"T"`/`t` en `"a b"`/`a_b` vallen niet samen), BLK-I (de poort keurt pas goed als samenvoegen nu kan, trekt goedkeuringen paginerend in bij elke weigering, fout, concept-PR of mislukte merge; mislukt het intrekken, dan faalt de sweep). **Besluit over betekenis van 'additief':** nieuwe objecten, kolommen, constraints en indexen gelden als additief (ook als ze latere schrijfacties kunnen laten falen, binnen één transactie); wijzigen of verwijderen van bestaande definities of gegevens niet.
- [x] Elfde reparatieronde (QA ronde 11): BLK-J (namen met drie delen worden geweigerd in plaats van afgekapt), `blocked` telt als samenvoegbaar voor de poort (verplichte goedkeuring ontbreekt dan nog), mislukt intrekken geeft exitcode 1 op alle paden. Eerst controleren bij de eerste bootstrap-run: dat de branchregels samenvoegen na de goedkeuring van de poort toestaan.
- [x] Twaalfde reparatieronde (QA ronde 12): BLK-K (zonder `destructief: true` alleen triggerfuncties: een nieuwe functie met een passender argumenttype overschrijft anders elke bestaande aanroep, bijv. `lower(varchar)`; `OWNED BY` alleen op een tabel uit dezelfde migratie).
- [x] Dertiende reparatieronde (QA ronde 13): BLK-L (functies hebben een eigen naamruimte en maken een tabel niet 'nieuw'; triggerdoel uit de vaste syntaxis, niet het eerste `on`; `comment on function` eist naam én argumenten; bodies van triggerfuncties mogen geen comment/create/lock/set e.d.; geen tijdelijke views; bijwerkingsfuncties `pg_advisory*`, `pg_sleep*`, `pg_notify`, … verboden). Bekend en aanvaard: `select … for update` en een `add column … default <vluchtige functie>` binnen de transactie.
- [x] Veertiende reparatieronde (QA ronde 14): BLK-M (`ts_rewrite` voert tekst als SQL uit; `create type … as range`/basistype maakt verborgen functies; `LIKE … INCLUDING` kopieert `nextval`-standaarden; `check_function_bodies` niet meer toegestaan; een migratie mag het ledger van de migratieroute niet noemen). **Bekende grens:** een nieuwe tabel/view/type in `public` met dezelfde naam als een object in een later schema van het zoekpad (bijv. een extensie-schema) verbergt dat object; de scanner kent de bestaande objecten niet.
- [x] Vijftiende reparatieronde (QA ronde 15): BLK-N. Het additieve repertoire is bewust klein gemaakt: nieuwe tabellen (zonder LIKE INCLUDING/PARTITION OF/INHERITS/AS SELECT), indexen, enum-/samengestelde typen, sequenties, `alter table … add …` (primaire sleutel alleen op eigen tabellen), rijen invoegen, commentaar en RLS op objecten uit dezelfde migratie (relaties en typen apart gevolgd). **Functies, triggers en views vragen voortaan `destructief: true`** (een nieuwe functie of view kan een bestaande aanroep of naam overnemen of rijen blootleggen onder standaardrechten). Namen met underscore vooraan, `pg_try_advisory*`, `pg_logical_emit_message`, `brin_*`, `pg_ls_*` geweigerd; `create extension` met beschermd schema ook mét destructief geweigerd. **Aanvaarde grenzen:** een index of kolom toevoegen aan een bestaande gepartitioneerde/overervende tabel koppelt bestaande partitie-indexen/kolommen aan de ouder; `select … for update`; vluchtige standaardwaarden; objecten in `public` die een gelijknamig object in een later zoekpad-schema verbergen.
- [x] Zestiende reparatieronde (QA ronde 16): BLK-O. De ALTIJD_VERBODEN-grens geldt ook met `destructief: true` voor: `auth.uid()` & co. herdefiniëren/laten vallen/rechten geven (de vrijstelling geldt alleen voor aanroepen), beschermde schema's als doel (DROP/ALTER/GRANT/COMMENT … SCHEMA auth, vault, storage, extensions), rollen/extensies/publicaties droppen, rollidmaatschap (`grant x to y`), `create extension` in een body, de rollencatalogus; `create table … as (select …)` geweigerd. Tweede laag in de migratieroute: een migratierol met standaardrechten die nieuwe tabellen aan een andere rol geeft, past niets toe (een kopie van bestaande rijen zou direct leesbaar zijn). **Besluit:** rijen uit een bestaande tabel in een nieuwe tabel invoegen (`insert … select`) is additief; de blootstelling wordt begrensd door die rolcontrole.
- [x] Zeventiende reparatieronde (QA ronde 17): BLK-P. ALTIJD_VERBODEN: zoekpad met een tekstwaarde, elk DDL-/rechtenstatement dat een beschermd schema of auth noemt (ook in een lijst of body), rollidmaatschap in bodies, `create or replace rule`, gebruikersinstellingen met een punt (`request.jwt.claim.sub`), `row_security`, reset/listen/notify, `import foreign`, rechten op database/server/taal, schema's van platformextensies, `crosstab` e.d. Additief: een index wordt niet als 'eigen relatie' gevolgd (hij woont in het schema van zijn tabel); CTAS met geneste haakjes geweigerd. **Aanvaard:** een tekst die als `regclass` naar een beschermd object verwijst (`'jarvis.x'::regclass`) is voor de scanner onzichtbaar; de rolcontrole (geen USAGE op jarvis) is daar de tweede laag.
